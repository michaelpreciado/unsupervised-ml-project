Inside the model

Clustering is usually invisible: you hand it data, it hands back labels, and you take the grouping on faith. These four views are what it looks like when you don't.

The feature space

Every image in this project is a point — 3 numbers for mean RGB, 216 for a histogram. Distance in that space is what "looks similar" means here. Below is that space flattened onto its two highest-variance directions with PCA, which is the only way to actually look at it.

  • library tile, at its true mean colour
  • cluster centroid — the model, in k points
  • cluster extent
  • a cell of your target, asking for colour

Convergence

Lloyd's algorithm alternates two steps — assign every tile to its nearest centre, then move each centre to the mean of what it was given. Inertia (cyan) can only fall; reassignments (blue bars) are what actually reach zero.

Ten different answers

k-means finds a local minimum, and which one depends entirely on where the centres started. It's run 10 times from different k-means++ seeds and the lowest-inertia fit wins. Each bar is one restart.

Choosing k

Inertia always improves with more clusters, so it can only show an elbow — never pick a value. Silhouette measures how much closer a tile is to its own cluster than the next one over, and it can peak.

What variety costs

Left alone, greedy matching hands the same flattering tile to hundreds of cells. The penalty taxes each reuse — which means deliberately giving some cells a worse tile. This is the trade, priced.

How it works

target image grid of cells feature per cell
source photos square thumbnails k-means clustering
matching render + animate

  1. Grid

    The target is resized so the mosaic is exactly n tiles wide, then cut into tile size squares. Fixed tile size, not fixed grid count — it keeps matching and rendering simple.

  2. Sources

    Every source photo is centre-cropped square and thumbnailed to the same tile size, so cells and tiles are directly comparable.

  3. Features

    Cells and tiles are embedded in one feature space, which turns "visually similar" into "close in euclidean distance". mean RGB is 3 numbers per image — the simplest thing that works. histogram is a 216-dim joint RGB histogram that captures colour distribution, so a half-red/half-blue tile stops matching a uniform purple cell. Its bins are soft: hard bin edges made two nearly identical colours either side of a boundary look as different as red and blue, which measurably beat up the mosaic.

  4. Clustering — the unsupervised core

    k-means partitions the tile library by visual similarity. No labels anywhere: the structure comes purely from the data. k-means++ seeding, restarts kept by lowest inertia, Lloyd iterations to convergence — the same defaults as the scikit-learn model in the CLI.

  5. Matching

    Each cell finds its nearest cluster centroid first, then searches only inside that cluster — the coarse-quantization idea behind IVF approximate-nearest-neighbour indexes like FAISS, except the index here is the unsupervised model itself. A variety penalty, scaled from the data, handicaps tiles that have already been placed.

  6. Render + animate

    Tiles start scattered beyond the frame and ease into their slots on a staggered diagonal sweep — the browser twin of the Pygame animation in the repo, plus a corner signature so a saved clip carries its own attribution.

Does the clustering actually pay off?

The honest version: at demo scale, cluster-accelerated matching is often no faster on the clock than brute force — the distance matrix is small and loop overhead dominates. What clustering reliably cuts is distance computations, by roughly a factor of k. That converts into wall-clock wins as the library and the feature dimensionality grow, which is exactly why real ANN systems use this structure at million-vector scale. Turn up the tile count, the mosaic width and the histogram features and watch the gap move.

Run it locally

The Python version does the same thing with scikit-learn and Pygame, plus a --scan-k report (inertia + silhouette) for choosing k and --record for a watermarked capture. 

git clone https://github.com/michaelpreciado/unsupervised-ml-project
cd unsupervised-ml-project
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/make_demo_assets.py

.venv/bin/python -m src.main \
    --target assets/targets/demo_sunset.png \
    --sources assets/sources \
    --tile-size 16 --grid-cols 48 --k 8 --animate
